근거로 쓰지 않는다.

## 2. 항목별 근거

### 정확성과 안정성 11 → 16

- ad-hoc `ALTER TABLE`을 Alembic 리비전으로 대체하고 startup 을 fail-closed 로 바꿨다.
  실제 DB **복사본**에서 upgrade 멱등성(행 수 42/7960/11 전후 동일)과 rollback(exit 0)을
  확인했고, 원본 2개의 sha256 이 변하지 않음을 증명했다.
- 현재 모델과 반대인 `rename_username_to_login_id.py` 를 명시적 no-op 으로 정리했다.
- 수집 실패가 200 + 빈 값으로 성공을 가장하던 것을 503 `{error, resource}` 로 구분했다.
- 권한 정확성 결함 3건을 발견해 수정했다(아래 4절).

**감점 사유**: `main.py` 가 라우터 import 실패를 `except ImportError` 로 잡고 경고 한 줄만
남긴 뒤 기동한다. Windows 에서 셸 기능 전체가 빠진 채 "정상 기동"으로 보이는 것을 이
세션에서 실제로 겪었다. 기능 부재를 사용자가 화면에서 눌러봐야 아는 구조다.

### 보안 4 → 17

가장 크게 오른 항목이며, **추정이 아니라 실행으로** 확인했다.

- 기본 자격 증명 제거, `SECRET_KEY` placeholder 거부(fail-closed).
- 토큰·ticket 비노출을 **실제 발급값 원문 대조**로 확인했다. backend 로그 37,150자와
  Nginx 로그에서 access token 2개·ticket 2개 전부 부재, URL 쿼리 0건, `Bearer` 0건.
- 권한 행렬 21개 경로 × 4가지 호출자를 **override 없는 실제 의존성 체인과 실제 로그인
  토큰**으로 검사한다(86 PASS).
- WebSocket ticket: 60초·일회성·용도 바인딩. 재사용 거부, 용도 교차 거부, 인증 전
  데이터 미전송을 실서버로 확인했다.
- 셸 컨테이너 격리 18/18. `CapEff=0000000000000000`, `NoNewPrivs=1`, 네트워크 `lo` 만,
  Docker 소켓 부재, `/tmp` noexec 를 커널 상태로 확인했다.
- 운영 TLS fail-closed 를 실제 컨테이너에서 확인(인증서 없으면 `Exited (1)`).
  backend 는 `PortBindings={}` 로 호스트 게시가 없다.

**감점 사유**
- 로그아웃이 서버 측 토큰 무효화를 하지 않는다. 유출된 토큰은 만료까지 유효하다.
- 세션 한도와 마지막 활성 admin 보호가 **단일 프로세스 메모리·락** 기준이다.
  다중 worker·다중 인스턴스에서는 보장되지 않는다.
- Git 이력의 과거 커밋에는 제거 전 blob 이 남아 있다(이력 재작성은 범위 밖).

### 구조와 유지보수성 10 → 11

- `pages/Filesystem.jsx` 952 → 307 줄. `features/` 아래 filesystem·network-diagnostics·
  users 모듈로 순수 함수와 컴포넌트를 분리했다.
- 공통 `apiFetch` 계층으로 인증 헤더·timeout·오류 타입·전역 401 처리를 한 곳에 모았다.
- 미사용 의존성 3개와 미사용 CSS 2개를 제거했다.

**감점 사유**: 최대 파일이 여전히 크다. `pages/Network.jsx` 492줄, `routers/shell.py`
484줄이며 후자는 pty·Docker 실행·라우트·세션 한도를 한 파일에서 다룬다. 계획에 없어
손대지 않았다.

### 성능과 자원 효율 7 → 11

- 연결마다 psutil 을 부르던 구조를 단일 `MetricsCollector` 의 5초 fan-out 으로 바꿨다.
- 블로킹 psutil 과 셸 컨테이너 start/cleanup 을 `asyncio.to_thread` 로 offload 했다.
- 모니터링 WebSocket **50개 동시 연결 50/50 성공**을 실제로 측정했다.

**감점 사유**: 부하 측정이 Windows 개발 호스트 기준이라 대상 배포 환경(라즈베리 파이)의
수치가 아니다. 측정된 REST 지연 1,109ms 는 판정 근거로 쓸 수 없다. 번들은 여전히
500kB 초과 단일 chunk(recharts·xterm)이며 분할하지 않았다.

### 테스트와 관측 가능성 5 → 11

- backend 191 + frontend 99 = **290 테스트**. 최초에는 실행조차 실패하는 스크립트였다.
- 핵심은 수가 아니라 종류다. `test_authorization_matrix_e2e.py` 는 의존성 override 를
  전부 제거하고 실제 앱·실제 DB·실제 토큰으로 계약을 검사한다. **이 검사가 없었다면
  이번에 찾은 권한 결함 3건 중 최소 2건은 그대로 남았다.**
- `bash scripts/gate.sh` 로 10개 검사를 1회에 실행한다. 줄바꿈과 무관한 공백 검사와
  미추적 파일 검사를 포함해 기존 `git diff --check` 보다 넓다.
- 소스 비밀 스캐너가 CI 마지막 단계에서 fail-fast 로 동작하도록 구성돼 있다.

**감점 사유**: 이 항목의 나머지 절반인 **관측 가능성은 거의 그대로다.** 구조화 로그,
메트릭 익스포트, 추적, 오류 집계가 없다. 운영 중 문제를 사후에 파악할 수단이 부족하다.
또한 GitHub CI 는 push 미승인으로 **한 번도 실제 실행되지 않았다**(로컬 동등 명령으로만
검증). 브라우저 수준 검증은 사용자 결정으로 생략했다.

### 문서와 배포 9 → 12

- README 를 전면 개정하고 **경로를 OpenAPI 와 기계 대조해 양방향 차이 0건**을 확인했다.
  이전 README 는 `?token=<JWT>` 방식과 placeholder `SECRET_KEY` 를 안내하고 있었다.
- `docs/operations.md`(환경변수·로컬 개발·프로필·인증서·배포 후 확인),
  `docs/db-operations.md`(백업·검증·복구), `docs/tutorials/README.md`(7단계 과제)를 갖췄다.
- 과거 수동 테스트 보고서 2건은 삭제하지 않고 "현재 동작 아님" 표를 붙여 무엇이
  달라졌는지 명시했다.
- 배포 경계를 실제 컨테이너로 확인했다(fail-closed, HTTP→HTTPS 301, 보안 헤더 4종,
  8000 미게시).

**감점 사유**: `.gitignore` 정책상 계획·진행 기록·평가·`CLAUDE.md` 가 저장소에 들어가지
않는다. 새 기여자는 **무엇을 왜 그렇게 결정했는지** 저장소만으로는 알 수 없다.
`ws-access.log` 는 볼륨이 없어 컨테이너 제거 시 사라진다.

### 학습자 관점 요약

- **시작 가능성 15 → 20**: 로컬(Docker 없이)·개발·운영 세 경로와 문제 해결 표를 제공하고,
  검증을 명령 하나로 줄였다. 감점은 실제로 겪은 두 함정이다 — Windows 에서 셸이 조용히
  빠지는 것, 관리자 생성 명령이 무해한 트레이스백을 뱉는 것.
- **코드 이해 가능성 17 → 20**: 파일이 작아지고 보안 핵심부에 "왜"를 적은 주석이 생겼다.
  큰 파일 2개와 오래된 파일의 주석 편차가 남았다.
- **학습 효과 21 → 23**: 원래 강했던 항목이다. 7단계 과제, 권한 계약 문서, 그리고 실제
  취약점 3건의 발견-수정 기록이 더해졌다. 과제에 답을 넣지 않은 것은 의도이지만
  자습에는 규율이 필요하다.
- **안전한 실습과 확장 10 → 21**: 가장 크게 올랐다. 셸 격리를 커널 상태로 실증했고,
  시뮬레이션 기능에서 실제 실행 오인 문구를 제거했으며, "실패 테스트 → 구현 → 통과"
  절차가 문서와 과제에 반영됐다. 자동 채점이 없어 25 는 아니다.

## 4. 검증 중 발견해 수정한 결함

계획에 없던 발견이며, 셋 다 **기존 테스트는 통과하는데 실제로는 뚫려 있던** 경우다.
원인은 같다 — 테스트가 인증 의존성을 가짜로 바꿔치기해 실제 체인을 돌리지 않았다.

| 결함 | 영향 | 조치 |
| --- | --- | --- |
| `GET /api/monitor/processes` 무인증 200 | 호스트 PID·실행 파일명·자원 사용률 노출 | 라우터에 `get_current_user` 적용 |
| `/api/shell/reset`·`/sessions` 서명만 확인 | viewer 가 초기화 로직 진입, 비활성 사용자 통과 | `get_current_admin` 으로 교체, 미참조 헬퍼 제거 |
| 비활성 사용자에게 403 | 프런트가 401 에서만 세션을 정리하므로 세션이 남음 | 401 로 정정, 로그인도 계정 상태 oracle 제거 |

재발 방지는 `test_authorization_matrix_e2e.py` 다. 계약에 행을 추가하면 이 검사에도
추가해야 하고, 실제 체인으로 돌지 않으면 실패한다.

## 5. 남은 위험 (우선순위 순)

1. **로그아웃이 토큰을 무효화하지 않는다.** 유출 시 만료까지 유효하다. 서버 측
   블랙리스트 또는 짧은 만료 + refresh 구조가 필요하다.
2. **단일 프로세스 가정.** 셸 세션 한도, 마지막 활성 admin 보호, ticket 저장소가 모두
   프로세스 메모리 기준이다. 다중 worker·다중 인스턴스 배포에서 깨진다.
3. **관측 가능성 부재.** 운영 중 이상을 사후에 추적할 수단이 없다.
4. **CI 미실행.** workflow 는 있으나 push 미승인으로 실제 실행된 적이 없다.
5. **Windows 에서 셸 기능이 조용히 빠진다.** 배포 대상은 Linux 이지만 개발 환경에서
   혼동을 준다.
6. **대상 하드웨어 미측정.** 부하 판단은 개발 호스트 기준이다.
7. **Git 이력에 과거 blob 잔존.** 이력 재작성은 별도 결정이 필요하다.

## 6. 결론

두 관점 모두 목표를 넘겼다(시니어 78 ≥ 75, 학습자 84 ≥ 80).

점수보다 중요한 변화는 **검증의 성격**이다. 최초 평가 시점에는 실행되지 않는 테스트
스크립트와 코드와 어긋난 문서가 있었고, 개선 과정 대부분도 mock·정적 검사에 머물러
있었다. 이번 릴리스 검증에서 실제 서버·실제 컨테이너·실제 토큰·실제 DB 복사본으로
돌린 결과, **통과하던 테스트 뒤에 숨어 있던 권한 결함 3건**이 드러났다.

남은 위험 7건은 대부분 "단일 인스턴스 학습용 프로젝트"라는 전제에서 나온다. 이 전제가
바뀌는 순간(다중 인스턴스, 실사용자, 공개 서비스) 1·2·3번은 즉시 차단 사유가 된다.
