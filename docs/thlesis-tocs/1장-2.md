# 1. 서론

## 1.1 연구 배경

Linux는 서버, 클라우드 컴퓨팅, 네트워크 및 정보보안 분야에서 폭넓게 활용되는 운영체제로, 관련 분야의 전문 인력을 양성하기 위해 필수적으로 학습하여야 하는 기술 가운데 하나이다. 그러나 Linux를 처음 접하는 학습자는 그래픽 사용자 인터페이스(Graphical User Interface, GUI)를 중심으로 조작하는 Windows 운영체제와 달리 명령 줄 인터페이스(Command-Line Interface, CLI)를 기반으로 시스템을 제어하여야 한다는 점에서 어려움을 경험한다.

Windows 환경에서는 아이콘과 메뉴를 통해 기능의 위치와 실행 결과를 직관적으로 확인할 수 있으나, Linux 환경에서는 명령어의 의미와 사용 형식, 옵션, 디렉터리 구조 및 실행 결과를 학습자가 직접 이해하여야 한다. 특히 오타, 권한 문제, 경로 설정 오류 및 서비스 구성 오류는 초보 학습자가 문제의 원인을 파악하기 어렵게 만든다. 화면에 표시된 결과가 정상 상태인지 오류 상태인지를 판단할 기준을 아직 갖추지 못하였기 때문이다.

## 1.2 Linux 서버 운영 학습의 어려움

대학의 Linux 관련 교육은 제한된 수업 시간 안에 운영체제의 기본 개념, 주요 명령어, 파일 및 사용자 관리, 네트워크 설정, 서버 구축 등 다양한 내용을 다루어야 한다. 이로 인해 실제 교육은 가상머신에 Linux를 설치한 후 일부 기본 명령어를 실습하는 수준에 그치는 경우가 많다. 이 경우 학습자는 명령어의 실행 방법은 익힐 수 있으나 각각의 명령어가 시스템 상태에 어떠한 변화를 발생시키는지 충분히 탐색하기 어려우며, 서버 장애나 설정 오류와 같은 실제 운영 상황을 반복적으로 경험하기에는 시간적, 환경적 제약이 존재한다.

또한 Linux 서버 운영 학습은 단순한 명령어 암기만으로 이루어지지 않는다. 학습자는 시스템의 상태를 확인하고, 출력된 정보를 해석하며, 문제의 원인을 추론한 후 적절한 명령어를 선택하여 실행하여야 한다. 예를 들어 웹 서버가 정상적으로 동작하지 않는 상황에서는 프로세스 실행 여부, 서비스 상태, 네트워크 포트, 방화벽 정책 및 로그 등을 단계적으로 확인하여야 하므로 여러 명령어와 시스템 구성요소 간의 관계를 종합적으로 이해하는 능력이 요구된다. 그러나 초급 학습자는 어떤 정보를 먼저 확인하여야 하는지 판단하기 어렵고, 실행 결과의 의미를 해석하는 데에도 어려움을 겪는다.

여기에 실습 환경 자체의 부담이 더해진다. 실제 서버를 활용한 실습은 운영체제 설치, 가상머신 구성 및 네트워크 설정과 같은 사전 작업을 요구하므로, 본격적인 문제 해결 실습을 시작하기까지 높은 진입 장벽이 발생한다. 또한 초보 학습자가 서비스를 중지하거나 방화벽 규칙을 잘못 변경하면 환경을 복구하여야 하므로, 반복적인 연습이 가장 필요한 위험한 명령일수록 실습 대상에서 제외되기 쉽다.

## 1.3 기존 모니터링 도구의 한계

서버 운영 학습의 출발점은 서버의 상태를 관찰하는 일이며, 이를 지원하는 웹 기반 모니터링 도구는 이미 여러 종류가 널리 사용되고 있다. 그러나 이러한 도구가 상정하는 사용자는 서버를 운영하는 전문가이고, 본 연구가 상정하는 사용자는 Linux 서버 운영을 처음 학습하는 사용자이다. 대상 사용자가 서로 다르기 때문에 학습자는 화면에 표시된 값을 보더라도 그것이 정상적인 작업 부하인지 문제 상황인지 판단하지 못하며, 도구를 사용 가능한 상태로 구성하는 데에도 적지 않은 사전 지식을 요구받는다. 또한 무엇을 연습하여야 하는지와 자신의 시도가 옳았는지를 확인할 방법을 얻지 못한다. 이는 도구의 결함이 아니라 설계 목적의 차이이며, 개별 도구의 기능과 학습 목적에서의 차이는 2장에서 비교한다.

따라서 학습을 목적으로 한다면 실제로 동작 중인 서버의 자원 상태를 관찰할 수 있는 화면과 서버 운영을 실습하며 질문할 수 있는 경로가 하나의 환경 안에 함께 제공되어야 한다. 다만 본 연구는 이 가운데 실습과 질의응답을 결합하는 부분을 구현 범위로 삼았으며, 관찰 화면에 표시된 지표 값 자체를 질의 대상으로 삼는 기능은 구현하지 않고 6장에서 향후 과제로 제시한다.

## 1.4 생성형 AI 기반 학습 지원의 필요성

앞의 제약을 보완하기 위해서는 복잡한 실습 환경을 구축하지 않고도 Linux 명령어를 입력하고 그 결과를 확인할 수 있는 학습 환경이 필요하다. 이때 명령을 실제 시스템에서 실행하지 않고 서버가 보관하는 상태 위에서만 처리하면, 서비스 중지나 방화벽 변경과 같이 실제 환경에서 위험한 명령까지 학습 소재로 활용할 수 있으며 실패하더라도 환경을 복구할 필요가 없다. 이 경우 학습자가 확인하게 되는 것은 명령어 문법의 암기가 아니라 명령과 상태 변화의 대응 관계이다.

여기에 생성형 AI를 결합하면 학습자는 실습 도중 발생한 의문을 즉시 자연어로 질문하고 자신의 수준에 맞춘 설명을 받을 수 있다. 다만 대규모 언어모델은 사실과 다른 내용을 그럴듯하게 생성하며, 학습자는 설명의 옳고 그름을 스스로 판별할 능력이 아직 부족하므로 잘못된 설명은 일반 사용자보다 학습자에게 더 큰 피해를 준다. 따라서 학습 지원에 생성형 AI를 도입할 때에는 명령의 실행 결과와 성취 여부의 판정과 같이 사실을 확정하는 일은 결정적인 규칙에 맡기고, 생성형 AI는 확정된 사실을 설명하는 역할로 한정하여야 한다. 생성형 AI가 서버를 대신하여 실행 결과를 생성하거나 성취 여부를 직접 판단하도록 구성하면, 정확성 문제가 학습의 판정 결과에까지 그대로 전달되기 때문이다. 정답을 곧바로 제시하지 않고 단계적으로 안내하는 힌트 구조가 필요한 이유도 같은 맥락에 있으며, 이러한 판단의 근거가 되는 선행 연구는 2장에서 정리한다.

## 1.5 본 연구의 목적

본 연구는 Linux 입문 단계의 대학생과 Linux 서버 운영 초급자를 대상으로, 복잡한 실습 환경 구축 없이 웹 브라우저만으로 서버의 자원 상태를 관찰하고 Linux 명령어와 서버 운영 과정을 학습할 수 있는 생성형 AI 기반 학습 지원 시스템을 제안하는 것을 목적으로 한다.

제안하는 시스템은 세 가지 요소를 중심으로 구성된다. 첫째, 실제로 동작 중인 서버의 자원 사용량을 주기적으로 수집하여 웹 화면에 실시간으로 제공한다. 학습자는 서버를 직접 구축하거나 소유하지 않아도 CPU와 메모리 사용량 및 프로세스 목록이 시간에 따라 어떻게 변화하는지를 관찰할 수 있다.

둘째, 학습자가 입력한 명령을 실제 시스템에서 실행하지 않고 서버가 보관하는 가상 Linux 상태를 전이시키는 방식으로 실습을 구성한다. 성취 여부는 학습자가 어떤 명령 문자열을 입력하였는지가 아니라 최종 가상 상태가 목표 상태에 도달하였는지를 기준으로 판정하므로, 서로 다른 명령이나 절차를 사용하더라도 동일한 목표 상태에 도달하면 정답으로 인정된다. 상태 전이와 채점의 구체적인 규칙은 3장에서 기술한다.

셋째, 생성형 AI는 이와 같이 확정된 상태와 판정을 학습자에게 설명하는 역할을 담당한다. 학습자가 실습 도중 발생한 의문을 자연어로 질문하면 시스템이 현재 가상 상태와 확정된 판정을 함께 입력으로 전달하므로 학습자가 자신의 상황을 다시 설명할 필요가 없다. 단계별 힌트는 정답을 곧바로 제시하지 않고 한 단계씩 공개하며, 생성형 AI는 해당 힌트에 대한 부연 설명을 제공한다. 명령의 실행 결과를 생성하거나 성취 여부를 판정하는 일에는 생성형 AI가 관여하지 않는다.

이와 별도로 제한된 환경에서 실제 명령을 실행해 볼 수 있는 웹 터미널을 제공한다. 명령은 호스트가 아니라 세션마다 새로 생성되는 격리된 컨테이너에서 실행되며, 해당 컨테이너에는 네트워크 차단, 읽기 전용 루트 파일시스템, 커널 권한 제거, 권한 상승 금지, 비특권 사용자 실행 및 메모리·CPU·프로세스 수 제한을 적용한다. 다만 실제 명령 실행은 시스템에서 가장 위험한 기능이므로 관리자 권한을 가진 사용자에게만 허용하며, 일반 학습자의 기본 학습 경로는 가상 실습이다. 두 기능은 서로 상태를 공유하지 않는다.

이를 통해 Linux 학습을 위한 환경 구성 부담을 줄이고, 실제 환경에서는 시도하기 어려운 서버 장애 상황까지 반복적으로 실습할 수 있는 기회를 제공하고자 한다. 아울러 서버 상태를 관찰하는 화면과 실습 및 질의응답 기능을 하나의 웹 시스템에 통합함으로써, 학습자가 자신의 실습 상황을 다른 도구에 옮겨 설명하지 않고 하나의 환경에서 학습을 이어 갈 수 있도록 하는 것을 의도한다. 다만 이러한 통합은 실습 기능에 한정되며, 모니터링 화면은 생성형 AI 기능과 연결되어 있지 않다.

다만 본 연구가 수행한 것은 시스템의 설계와 구현이며, 실제 학습자를 대상으로 한 사용성 평가나 학습 효과 검증은 수행하지 않았다. 따라서 본 논문은 학습 효과에 관한 주장을 제시하지 않으며, 해당 항목은 5장과 6장에서 한계 및 향후 과제로 다룬다.

이후 본 논문의 구성은 다음과 같다. 2장에서는 관련 연구와 기술 배경을 정리하고 기존 연구와의 차별성을 밝힌다. 3장에서는 제안 시스템의 설계를, 4장에서는 구현한 주요 기능과 검증 결과를 기술한다. 5장에서는 학습에 적용하였을 때의 기대 효과와 한계를 정리하고, 6장에서 결론과 향후 개선 방향을 제시한다.
