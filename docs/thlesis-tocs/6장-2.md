# 6. 결론

본 논문은 실시간으로 수집한 시스템 자원 데이터를 웹 화면으로 제공하고, 가상 Linux 상태 위에서 이루어지는 실습에 생성형 AI 기반 설명 기능을 결합한 학습 지원 시스템을 설계하고 구현하였다. 본 장에서는 개발의 의의를 정리하고 남은 과제를 향후 개선 방향으로 제시한다.

의의를 서술하기에 앞서 본 연구가 주장하지 않는 것을 밝힌다. 본 연구는 실제 학습자를 대상으로 한 사용성 평가와 학습 효과 검증을 수행하지 않았으며, 생성형 AI가 생성한 설명의 정확성도 평가하지 않았다. 따라서 아래의 의의는 측정된 효과가 아니라 구현으로 확인한 구성상의 의의이며, 평가에 해당하는 항목은 향후 개선 방향으로 제시한다.

## 6.1 개발의 의의

첫째, 서버 상태를 시각화하는 기능과 그 상태를 자연어로 설명하는 기능을 서로 다른 도구로 나누지 않고 하나의 시스템으로 구성하였다. 인증, 모니터링, 이력 조회, 웹 터미널, 가상 실습, 생성형 AI 질의응답이 모두 하나의 백엔드 애플리케이션에서 동작한다. 이 구성에서 학습자는 자신의 실습 상황을 다른 도구에 옮겨 설명할 필요가 없다. 학습자가 질문하면 서버가 보관하고 있던 현재 가상 상태와 서버가 확정한 판정이 함께 모델 입력으로 전달되기 때문이다. 다만 이러한 통합은 실습 기능에 한정되며, 모니터링 화면은 생성형 AI 기능과 연결되어 있지 않다.

둘째, Linux 서버를 소유하지 않은 학습자도 실제로 동작 중인 서버의 자원 상태를 관찰할 수 있는 경로를 제공하였다. 화면에 표시되는 값은 예시 데이터가 아니라 실제 호스트에서 주기적으로 수집한 값이다. 또한 자원 수집에 실패한 경우를 값이 0인 경우와 구분하여 표시하고, 연결이 유지되더라도 새로운 데이터가 도착하지 않으면 응답 없음으로 표시한다. 값이 0인 상태와 값을 알 수 없는 상태를 구분하는 것은 모니터링에서 익혀야 할 판단이며, 이를 화면 수준에서 분리한 것이 설계상의 선택이다. 다만 자원 지표의 의미를 자연어로 설명하는 기능은 구현하지 않았으며, 이는 2장에서 정리한 요구 중 충족하지 못한 부분이다.

셋째, 모니터링 기능과 생성형 AI 실습 도우미를 결합하는 방식에 의의가 있다. 생성형 AI를 학습 기능에 도입할 때 가장 단순한 구성은 모델이 학습자의 성취 여부까지 판단하도록 하는 것이지만, 본 시스템은 판정과 설명을 분리하였다. 성공, 부분 성공 및 실패의 판정은 서버의 규칙 기반 채점기가 최종 가상 상태를 기준으로 결정하고, 언어모델은 확정된 판정을 설명한다. 언어모델을 호출하는 지점은 질문과 힌트 두 곳이며 명령 처리와 채점은 모델을 호출하지 않는다.

이러한 분리에서 세 가지 성질이 도출된다. 첫째, 같은 입력에 대해 같은 판정이 나오는 재현성이다. 둘째, 모델 호출이 실패하더라도 문제 제시와 명령 처리, 채점 및 규칙 기반 힌트는 그대로 동작하는 가용성이다. 셋째, 학습자가 프롬프트를 통해 판정을 변경할 수 없다는 점이다. 학습자의 입력을 지시가 아닌 데이터로 취급하도록 프롬프트에 명시하고 있으나, 그 지시를 모델이 따르지 않더라도 판정 경로 자체가 모델을 거치지 않으므로 성취 판정은 변경되지 않는다.

넷째, 서버 운영 교육에서 생성형 AI를 활용하는 개발 사례를 제시하였다. 모델에 전달하는 입력을 구조화된 항목으로 한정한 점, 응답에서 정의된 네 항목만 허용하고 그 외의 항목이 포함되면 응답 전체를 거부한 점, 호출이 실패한 경우 규칙 기반 안내로 대체하고 그 사실을 화면에 표시한 점, 사용자 단위로 호출량을 제한한 점이 구현에 포함되어 있다. 또한 호출 기록에 프롬프트 본문과 응답 원문, 학습자 입력을 저장하지 않고 해시 식별자와 지연 시간, 시도 횟수 및 실패 사유만 남겨 운영에 필요한 정보와 학습자의 입력 내용을 분리하였다.

## 6.2 향후 개선 방향

향후 개선 방향은 5장에서 밝힌 한계와 대응한다. 이 가운데 앞의 세 항목은 기능을 추가하는 일이 아니라 이미 구현한 것을 사람과 데이터로 확인하는 일이므로 우선순위가 높다.

첫째, 실제 학습자를 대상으로 한 사용성 평가가 필요하다. 지금까지 확인한 것은 시스템이 설계한 방식대로 동작하는지이며, 학습자가 화면 구성을 이해하는지, 가상 실습과 실제 서버의 구분을 인지하는지, 힌트를 어느 시점에 요청하는지는 확인하지 않았다. 특히 실습이 시뮬레이션이라는 고지를 화면에 항상 표시하고 있으나, 이 고지가 학습자에게 의도대로 인식되는지는 표시 여부와 별개의 문제이므로 확인이 필요하다.

둘째, 학습 전후 비교를 통한 학습 효과 검증이 필요하다. 본 논문은 학습 효과에 관한 주장을 하지 않았으며 이는 근거가 없기 때문이다. 사전 및 사후 평가를 설계하고 본 시스템을 사용한 집단과 실습 환경만 제공한 집단을 비교하여야, 5장에서 설계상의 차이로만 서술한 부분을 효과의 차이로 제시할 수 있다. 이때 실습 환경만 제공하는 방식, 일반적인 생성형 AI 대화 도구를 함께 사용하는 방식, 본 시스템의 세 가지가 비교군의 후보가 된다.

셋째, 생성형 AI 응답의 정확성 평가가 필요하다. 현재의 응답 검증은 정의된 항목과 형식을 지키는지만 확인하며 설명의 내용이 사실인지는 검사하지 않으므로, 형식 검증을 통과한 응답에 잘못된 설명이 포함되어 있으면 그대로 학습자에게 전달된다. 따라서 전문가가 응답 표본을 검토하여 오류의 유형과 빈도를 확인하고, 힌트가 학습 단계에 적합한지를 함께 판단하여야 한다. 평가 결과에 따라 자주 나타나는 오류 유형을 프롬프트에서 제약하거나 특정 개념에 대해서는 규칙 기반 설명을 우선하는 방안을 검토할 수 있다. 한편 언어모델을 사용하는 두 방식을 비교하는 실험을 시도한 기록이 있으나 모든 응답이 형식 검증을 통과하지 못하여 유효한 표본을 얻지 못하였다. 따라서 본 논문은 해당 결과를 근거로 사용하지 않았으며, 응답 형식을 안정적으로 확보하는 것이 정확성 평가에 선행되는 과제이다.

넷째, 생성형 AI가 설명할 수 있는 대상의 확장이 필요하다. 현재 설명 대상은 가상 실습 상태와 그에 대한 판정으로 한정된다. 먼저 Linux 시스템 로그 설명 기능을 검토할 수 있다. 실제 서버 운영에서 상태 확인 다음에 오는 것이 로그 확인이지만, 현재 가상 상태 엔진은 로그를 상태 항목으로 표현하지 않으므로 실습에서 로그를 다루지 못한다. 로그를 다루기 위해서는 상태 항목을 추가하는 것만으로는 부족하며 상태 변화에 따라 어떠한 로그가 기록되는지를 함께 정의하여야 한다.

다음으로 모니터링 지표에 대한 자연어 해설이 필요하다. 현재 모니터링 화면은 생성형 AI 기능과 연결되어 있지 않아 학습자가 특정 지표의 의미를 질문할 수 없으며, 이는 2장에서 학습용 모니터링 도구에 필요하다고 정리한 요구 중 충족하지 못한 부분이다. 여기에는 두 가지가 함께 처리되어야 한다. 하나는 화면 표시 항목으로, 버퍼와 캐시는 수집 단계에서 사용량과 분리되어 전달되지만 화면에 표시되지 않으므로 학습자가 가장 혼동하기 쉬운 구분이 드러나지 않는다. 모니터링 이력 또한 1분 간격으로 저장한 스냅샷을 조회하는 세 가지 경로가 있으나 이를 호출하는 화면이 없어, 학습자가 화면에서 확인할 수 있는 추이는 화면을 열어 둔 동안 수신한 값으로 한정된다. 두 항목 모두 데이터와 조회 경로는 이미 갖추어져 있으므로 화면을 추가하는 범위에서 해소할 수 있으며, 지표 해설을 도입하려면 해설의 대상이 될 화면이 먼저 존재하여야 한다는 점에서 선행 과제에 해당한다. 다른 하나는 입력 범위의 결정이다. 현재 모델 입력에는 실제 서버의 자원 값이 포함되지 않으며 이는 실제 호스트의 상태를 외부 서비스로 전달하지 않기 위한 선택이므로, 지표 해설을 도입하려면 실제 수집값을 전달할 것인지 또는 지표의 일반적 의미만 설명할 것인지를 먼저 결정하여야 한다.

다섯째, 사용자 수준에 따른 설명 난이도 조절이 필요하다. 현재도 학습자 수준 값과 해당 세션의 최근 채점 이력이 모델 입력에 포함되며, 프롬프트는 이 값들을 설명의 깊이와 어조를 조정하는 데에만 사용하고 판정을 변경하는 데에는 사용하지 않도록 명시한다. 그러나 수준 값은 세션을 시작할 때 학습자가 지정하고 이후 채점 결과에 따라 이동한 다음 문제의 난이도로 갱신되며, 문제의 난이도는 시나리오의 순서에 따라 부여되므로 학습자의 실제 이해도를 나타내지는 않는다. 또한 학습자가 어떤 개념을 반복적으로 틀렸는지를 서버가 분류하는 기능은 구현하지 않았으며, 서버는 문제별 판정 이력이라는 구조화된 사실만 제공한다. 따라서 시도 이력과 힌트 사용 단계로부터 이해도를 추정하여 수준 값을 갱신하는 방향과, 오답을 개념 단위로 분류하여 반복적으로 틀리는 개념을 서버가 식별하는 방향을 검토할 수 있다. 후자는 문제 정의에 개념 식별자를 부여하는 작업이 선행되어야 하며, 학습 시나리오가 코드와 분리된 정의 파일로 관리되므로 코드 수정 없이 확장할 수 있는 구조이다.

여섯째, 서버 장애 상황별 학습 콘텐츠의 확대가 필요하다. 현재 제공되는 문제는 세 시나리오의 여섯 문제로 정규 교육 과정을 대체하기에는 부족하다. 확대에는 두 가지 방향이 있으며 난이도가 서로 다르다. 하나는 현재의 상태 항목으로 표현 가능한 범위에서 문제를 추가하는 것으로 시나리오 정의 파일에 항목을 추가하는 것으로 가능하다. 다른 하나는 상태 항목 자체를 확장하는 것으로 가상 상태 엔진과 상태 전이 규칙, 채점 규칙을 함께 확장하여야 한다. 자원 고갈이나 성능 저하와 같이 시간에 따라 변화하는 상황은 현재의 상태 표현 방식으로 다루기 어려우므로 후자에 해당한다. 다만 콘텐츠를 확대하더라도 여러 요인이 얽힌 실제 장애의 원인 진단은 본 방식의 범위를 벗어난다. 상태 전이가 결정적이라는 성질이 판정의 재현성을 보장하는 근거이므로, 원인과 결과가 명확히 대응하지 않는 상황을 다루기 위해서는 판정 방식 자체를 다시 설계하여야 한다.

한편 본 시스템은 단일 인스턴스 학습용으로 설계하였으므로, 실사용자를 대상으로 하는 환경으로 전제가 변경되는 경우 다음 항목이 선행되어야 한다.

| 선행 과제 | 현재 상태 |
| --- | --- |
| 로그아웃 시 토큰 무효화 | 서버 측 무효화 목록이 없어 유출된 토큰은 만료 시점까지 유효하다 |
| 다중 인스턴스 지원 | 세션 한도와 마지막 관리자 보호, 티켓 저장소가 프로세스 메모리 기준이다 |
| 관측 가능성 확보 | 구조화 로그와 메트릭, 추적 기능이 없어 운영 중 이상을 사후에 추적하기 어렵다 |
| 전송 구간 암호화 | 인증서 부재 시 기동을 중단하는 설계는 포함되어 있으나, 배포 환경이 고정 IP만 사용하여 해당 경로를 적용하지 못하였다 |

본 연구는 실시간 시스템 모니터링 데이터를 제공하는 웹 인터페이스와 가상 Linux 상태 위에서 동작하는 규칙 기반 실습 및 채점 구조, 그리고 이에 결합한 생성형 AI 설명 기능을 하나의 시스템으로 설계하고 구현하였다. 판정은 규칙이 결정하고 설명은 언어모델이 담당하도록 역할을 분리한 구성이 본 시스템의 특징이며, 이 구성이 학습에 실제로 어떠한 효과를 갖는지는 향후 개선 방향에서 제시한 평가를 통해 확인하여야 할 과제로 남는다.
