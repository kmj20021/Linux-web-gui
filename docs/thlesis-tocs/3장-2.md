# 3. 시스템 설계

본 장에서는 Linux 서버 모니터링과 생성형 AI 기반 학습 기능을 제공하기 위한 시스템의 전체 구조와 주요 설계 내용을 설명한다.

시스템 설계의 핵심 원칙은 두 가지이다. 첫째, 서버 상태와 학습자의 성취 여부는 서버 내부의 규칙에 따라 판정하며, 생성형 AI는 확정된 결과를 설명하는 역할만 수행한다. 둘째, AI 학습 기능에서 입력한 명령어는 실제 Linux 서버에서 실행하지 않고 가상 상태를 변경하는 용도로만 사용한다. 이를 통해 생성형 AI의 부정확한 판단과 실습 과정에서 발생할 수 있는 시스템 위험을 줄이고자 하였다.

## 3.1 전체 시스템 구조

시스템은 React 기반 프론트엔드, FastAPI 기반 백엔드, SQLite 데이터베이스, 가상 Linux 상태 엔진 및 Amazon Bedrock으로 구성된다. 사용자는 웹 브라우저를 통해 서버 상태를 확인하거나 Linux 관련 질문과 실습 명령을 입력한다.

프론트엔드는 서버 모니터링 화면과 AI 학습 화면을 제공한다. 백엔드는 Linux 서버 상태를 수집하고, 사용자 요청을 처리하며, 필요한 정보를 Amazon Bedrock에 전달한다. 데이터베이스에는 사용자 정보, 서버 상태 이력, 학습 세션 및 명령 입력 기록 등을 저장한다.

시스템의 데이터 흐름은 세 가지로 구분된다.

첫째, 실제 서버의 CPU, 메모리, 디스크 및 네트워크 상태를 수집하여 사용자화면에 전달하는 모니터링 경로이다. 둘째, 학습자가 입력한 명령에 따라 가상 Linux 상태를 변경하고 결과를 판정한 뒤, 확정된 가상 상태와 판정 결과를 생성형 AI에 전달하여 자연어 설명을 생성하는 학습 경로이다. 이때 성취 여부의 판정은 서버가 수행하고 생성형 AI는 그 결과를 설명하는 역할만 맡는다. 셋째, 학습자가 실제 명령을 입력해 보는 웹 터미널 경로로, 명령은 호스트가 아닌 격리된 컨테이너 안에서 실행된다.

생성형 AI 호출에 실패하더라도 서버 상태 확인과 가상 실습 기능은 계속 동작하도록 각 기능을 독립적으로 구성하였다.

## 3.2 서버 상태 수집 및 데이터 전달

시스템은 Linux 서버의 CPU 사용률, 메모리 사용량, 디스크 사용량, 네트워크 상태 및 주요 프로세스 정보를 수집한다. 수집한 데이터 가운데 CPU와 메모리 사용량 및 주요 프로세스 정보는 일정 주기로 데이터베이스에 저장하여 자원 사용 추이를 조회할 수 있도록 하였다. 저장된 데이터는 시간이 지날수록 계속 증가하므로 보존기간을 정하고, 기간이 지난 기록은 일괄 삭제한다.

여러 사용자가 동시에 접속할 때 사용자별로 데이터를 반복 수집하면 모니터링 기능 자체가 서버 부하를 증가시킬 수 있다. 이를 방지하기 위해 하나의 백그라운드 수집기가 일정한 주기로 서버 상태를 수집하고, 생성된 최신 데이터를 모든 사용자에게 공유하도록 설계하였다.

실시간성이 필요한 CPU와 메모리 등의 정보는 WebSocket을 통해 전달하고, 특정 시점의 정보나 이전 기록 조회에는 REST API를 사용한다. 백엔드는 수집한 원시 데이터를 화면에서 사용할 수 있도록 단위를 변환하고 정리한 후 프론트엔드에 전달한다.

React 기반 프론트엔드는 서버 상태를 수치를 그래프로 표현한다. 또한 WebSocket 연결이 중단된 경우 마지막으로 수신한 데이터를 현재 값으로 오해하지 않도록 연결 상태를 화면에 표시한다.

## 3.3 생성형 AI 기반 학습 지원

생성형 AI 기능에는 Amazon Bedrock을 사용한다. 백엔드는 학습자 수준, 현재 문제의 정의, 현재 가상 실습 상태, 서버가 판정한 결과, 학습자의 질문, 최근 대화 및 해당 세션의 채점 이력을 구조화하여 Amazon Bedrock에 전달한다.

생성형 AI는 서버 상태나 학습자의 성공 여부를 직접 판단하지 않는다. 성공, 부분 성공, 실패 등의 결과는 서버 내부의 규칙 기반 채점기가 결정하며, 생성형 AI는 해당 결과의 의미와 관련된 Linux 개념을 자연어로 설명한다. 생성형 AI를 호출하는 지점은 학습자의 질문, 힌트 요청, 그리고 시뮬레이터가 처리하지 못한 명령에 대한 설명 요청 세 가지로 한정하였다. 명령 처리와 채점은 생성형 AI를 호출하지 않고 서버 내부에서만 수행한다.

세 지점은 모두 규칙으로 결정된 사실이 확정된 뒤에 호출된다. 질문과 힌트 요청에서는 채점 결과가 먼저 확정되고, 설명 요청에서는 입력이 처리되지 않았다는 사실과 그 시점의 가상 상태가 먼저 확정된다. 설명 요청은 명령의 결과 코드가 성공이 아닐 때만 사용하며, 생성된 설명은 화면에 표시하고 시도 기록에 남길 뿐 가상 상태와 채점에는 관여하지 않는다. 명령 처리 경로 자체에 모델을 넣지 않고 처리 이후의 별도 요청으로 분리한 것은, 실습의 상태 전이가 모델의 응답 여부와 무관하게 완결되도록 하기 위해서다.

AI 학습 도우미는 다음과 같은 정보를 제공한다.

* 현재 가상 실습 상태에 대한 설명
* 서버가 확정한 채점 결과의 의미에 대한 설명
* 학습자의 질문에 대한 추가 설명
* 규칙 기반으로 제시된 단계별 힌트에 대한 부연 설명
* 시뮬레이터가 처리하지 못한 명령에 대한 참고용 설명
* 학습 이력을 반영한 설명 수준의 조정

생성형 AI가 설명하는 대상은 가상 실습 상태와 채점 결과이며, 실제 서버의 자원 사용량은 모니터링 화면에서 수치와 그래프로 제공한다.

생성형 AI의 응답은 화면 표시에 필요한 네 개 항목만 허용하는 형식으로 검증하며, 정의되지 않은 항목이 포함되면 응답 전체를 사용하지 않는다. 처리하지 못한 명령에 대한 설명 요청에는 다른 방식을 적용하여, 호출 자체에 도구 정의를 붙이고 모델이 반드시 그 도구를 호출하도록 지정한다. 이 경우 모델이 만들어 낼 수 있는 값은 화면에 표시할 문자열 하나로 한정되므로, 형식 준수가 모델의 협조가 아니라 호출 규약의 제약이 된다. 또한 학습자가 입력한 문장은 지시문이 아니라 데이터로 취급하도록 프롬프트 안에서 구분하여, 학습자가 판정 결과를 바꾸도록 모델에 지시하는 것을 방지한다. 호출 비용과 부하를 고려하여 사용자별로 동시 요청 수와 요청 간격도 제한하며, 세 호출 지점이 같은 제한을 공유한다.

생성형 AI가 잘못된 형식의 응답을 반환하거나 호출에 실패한 경우에는 AI 설명 대신 규칙 기반 안내를 표시한다. 다만 화면이 자동으로 보내는 설명 요청이 실패한 경우에는 학습자가 재시도할 방법이 없으므로 안내 문구를 표시하지 않고 아무것도 추가하지 않는다. 따라서 AI 기능을 사용할 수 없는 상황에서도 문제 제시, 명령 처리 및 채점 기능은 유지된다.

## 3.4 가상 Linux 실습 및 채점

AI 학습 화면에서 학습자가 입력한 명령어는 실제 Linux 서버에서 실행되지 않는다. 입력된 명령은 서버 내부에 저장된 가상 Linux 상태를 변경하는 데 사용된다.

가상 상태에는 서비스 실행 여부, 사용자 정보, 파일 권한, 방화벽 규칙, 열린 포트 및 패키지 설치 상태 등이 포함된다. 이 방식을 통해 서비스 중지나 방화벽 변경과 같이 실제 서버에서 실행하기 위험한 명령도 안전하게 학습할 수 있다.

명령 처리 과정에서는 허용된 명령과 인자만 사용할 수 있도록 제한한다. 명령 연결, 파이프, 리다이렉션 등 지원하지 않는 문법이 입력되면 명령을 거부하고 기존 가상 상태를 유지한다.

학습자의 수행 결과는 특정 명령어 문자열을 입력했는지가 아니라, 명령 수행 후 가상 상태가 목표 상태에 도달했는지를 기준으로 판정한다. 이를 통해 서로 다른 명령이나 절차를 사용하더라도 동일한 목표를 달성한 경우 정답으로 인정할 수 있다.

판정 결과는 성공, 부분 성공 및 실패로 구분한다. 부분 성공은 일부 조건은 충족했지만 추가 작업이 필요한 상태를 의미한다. 실패한 경우에는 개념 설명, 관련 명령어 종류, 구체적인 명령 형식의 순서로 단계별 힌트를 제공한다.

## 3.5 인증 및 실습 환경 보호

시스템은 사용자 인증과 권한 관리를 서버에서 수행한다. 프론트엔드에서 관리자 메뉴를 숨기거나 특정 화면 접근을 제한하더라도, 실제 권한 여부는 모든 요청에 대해 백엔드가 다시 확인한다.

실시간 데이터와 웹 터미널의 WebSocket 연결에도 인증 절차를 적용하여 인증이 완료된 사용자에게만 데이터를 제공한다.

가상 실습과 별도로 실제 명령어 실행 경험을 제공하는 웹 터미널은 호스트 서버가 아닌 격리된 컨테이너에서 실행한다. 해당 컨테이너에는 네트워크 차단, 읽기 전용 시스템 영역, 비관리자 사용자 실행 및 자원 사용 제한 등을 적용한다. 또한 웹 터미널은 시스템에서 가장 위험한 기능이므로 관리자 권한을 가진 사용자에게만 허용하며, 각 사용자는 자신의 세션에만 접근할 수 있다.

가상 Linux 실습은 실제 명령을 실행하지 않고 상태 변화만 학습하는 기능이며, 웹 터미널은 제한된 환경에서 실제 명령을 실행해 보는 기능이다. 두 기능은 서로 다른 목적을 가지며 Linux 서버 운영 학습 과정에서 보완적으로 활용된다.
