# 5. 적용 및 기대 효과

## 5.1 학습자가 서버 상태를 이해하는 과정

Linux 서버 운영을 처음 학습하는 사용자는 관리 권한을 가진 실제 서버에 접근하여 실습할 기회를 얻기 어렵다. 본 시스템은 학습자가 직접 서버를 구축하지 않더라도 현재 동작 중인 서버의 자원 상태를 관찰할 수 있는 환경을 제공한다.

대시보드에는 실제 호스트에서 수집한 CPU 사용률, CPU 코어 수, 부하 평균, 메모리 사용률과 용량 및 자원 사용량이 높은 프로세스 목록이 표시된다. 해당 정보는 5초 간격으로 갱신된다. 학습자가 확인하는 값은 미리 작성된 예시 데이터가 아니라 실제 서버에서 수집한 현재 자원 사용량이므로, 서버의 부하 변화에 따라 자원 사용량이 어떻게 달라지는지를 직접 확인할 수 있다.

모니터링 화면은 현재 값을 먼저 확인한 후 그래프를 통해 시간에 따른 변화 추이를 살펴보는 순서로 구성하였다. 다만 그래프가 다루는 범위는 화면을 열어 둔 동안 수신한 값으로 한정된다.

자원 정보 수집에 실패한 경우와 실제 측정값이 0인 경우는 서로 다르게 표시한다. WebSocket 연결이 유지되고 있더라도 일정 시간 동안 새로운 데이터가 수신되지 않으면 응답 없음 상태로 표시한다. 이는 화면에 남아 있는 이전 값을 현재 서버 상태로 오인하는 것을 방지하기 위한 것이다. 이와 같이 정상적인 측정값, 수집 실패 및 연결 이상을 구분하는 과정 자체도 서버 모니터링 학습의 일부가 된다.

Linux 명령어 학습은 가상 실습 기능을 통해 진행된다. 학습 시나리오는 서비스 장애 복구, 운영 계정과 파일 권한 구성, 방화벽과 원격 접속 장애의 세 가지로 구성되며, 각 시나리오에는 두 개의 문제가 포함된다. 학습자가 다루는 명령은 서비스 관리, 계정 관리, 권한 관리, 방화벽 설정, 상태 확인 및 패키지 관리 계열이다.

학습 결과는 입력한 명령어 문자열이 정답과 일치하는지가 아니라, 명령 처리 이후의 최종 가상 상태를 기준으로 판정한다. 따라서 학습자는 하나의 정해진 명령어를 암기하기보다 목표 상태에 도달할 수 있는 여러 방법을 시도할 수 있다.

예를 들어 방화벽 관련 시나리오에서 원격 접속 가능 여부는 서비스 실행 상태와 방화벽 규칙을 함께 반영하여 결정된다. 학습자는 서비스가 실행 중이고 방화벽에서도 해당 연결이 허용되어야 원격 접속이 가능하다는 사실을 단순한 설명이 아니라 실제 가상 상태의 변화를 통해 확인할 수 있다.

한편 실제 명령어를 실행할 수 있는 웹 터미널은 관리자 권한을 가진 사용자만 사용할 수 있다. 일반 학습자에게 제공되는 기본적인 명령어 학습 방식은 가상 실습이다. 이는 실제 명령 실행 기능이 시스템에서 가장 높은 위험을 가지는 기능이라는 판단에 따른 것이다.

## 5.2 단순 실습 환경 제공과 AI 학습 제공의 차이

실습 환경만 제공하는 방식에서는 학습자가 문제 해결 과정에서 막혔을 때 그 원인을 스스로 판단해야 한다. 명령 실행이 실패한 이유나 현재 상태가 목표 상태와 어떻게 다른지를 판단하지 못하면 학습 과정이 중단될 수 있다. 특히 초보 학습자는 이러한 판단에 필요한 지식이 충분하지 않을 수 있다.

일반적인 생성형 AI 대화 도구를 사용하는 경우에는 생성형 AI가 학습자의 현재 실습 상태를 직접 알 수 없다. 따라서 학습자가 자신의 상황을 직접 설명해야 하며, 전달한 설명이 부정확하거나 일부 정보가 누락되면 생성되는 답변도 실제 상황과 달라질 수 있다. 또한 생성형 AI가 학습 성공 여부를 직접 판단하도록 하면, 실제로는 목표 상태에 도달하지 않았음에도 성공한 것으로 잘못 안내할 가능성이 있다.

본 시스템은 실습 환경과 생성형 AI 설명 기능이 동일한 가상 상태 정보를 사용하도록 구성하였다. 다만 학습 결과를 판정하는 권한은 생성형 AI에 부여하지 않았다.

학습자가 질문을 입력하면 서버가 먼저 현재 가상 상태를 규칙에 따라 채점하여 성공, 부분 성공 또는 실패 여부를 확정한다. 그다음 확정된 판정 결과와 현재 상태 정보를 포함한 입력을 생성하여 언어모델을 호출한다. 따라서 학습자는 자신의 현재 상황을 별도로 다시 설명하지 않고도 학습 과정에서 발생한 의문을 자연어로 질문할 수 있다.

다만 명령이 정상적으로 처리된 결과에 대한 설명은 학습자가 질문하거나 힌트를 요청한 경우에만 생성된다. 학습자가 명령어를 입력할 때마다 언어모델이 자동으로 결과를 평가하는 방식은 사용하지 않는다.

예외는 시뮬레이터가 입력 자체를 처리하지 못한 경우이다. 이 경우에는 학습자가 요청하지 않아도 화면이 자동으로 설명을 요청하여 참고용 설명을 학습 도우미 영역에 추가한다. 명령이 처리된 경우와 달리 가상 상태가 전혀 변하지 않아 학습자가 다음 시도를 판단할 근거가 화면에 남지 않기 때문이다. 이 설명 역시 확정된 상태나 판정을 변경하지 않으며, 표시용이라는 사실을 화면 상단의 고지에 함께 명시한다.

질문과 힌트 요청 시에는 해당 학습 세션의 최근 채점 이력을 함께 전달한다. 같은 문제에서 반복적으로 실패한 학습자와 처음 문제를 시도하는 학습자에게 동일한 깊이의 설명을 제공하는 것은 적절하지 않을 수 있으므로, 최근 채점 이력을 설명의 깊이와 어조를 조정하기 위한 정보로 활용한다.

이때 최근 채점 이력은 설명을 조정하는 데에만 사용하며, 기존 판정 결과를 변경하는 데 사용하지 않도록 프롬프트에 명시하였다. 다만 학습자가 어떠한 개념을 반복적으로 틀리고 있는지를 서버가 직접 분류하는 기능은 구현하지 않았다. 서버는 문제별 판정 이력이라는 구조화된 사실만 언어모델에 제공한다.

또 다른 차이는 판정과 설명의 역할을 분리한 것이다. 성공, 부분 성공 및 실패 여부는 서버의 규칙 기반 채점기가 결정하고, 언어모델은 서버가 확정한 판정 결과가 의미하는 내용을 설명한다.

다만 위의 비교는 각 방식이 가지는 시스템 구성의 차이를 정리한 것이다. 실습 환경만 제공하는 방식, 일반적인 AI 대화 도구 및 본 시스템의 설명 품질을 실제 실험으로 비교한 결과는 아니다. 본 연구에서는 이러한 비교 실험을 수행하지 않았다.

## 5.3 활용 가능성

첫째, 본 시스템은 Linux 서버 운영 입문 교육에 활용할 수 있다. 가상 실습에서 입력한 명령은 실제 서버에서 실행되지 않으므로, 학습자가 서비스를 중지하거나 방화벽 규칙을 잘못 변경하더라도 실제 환경을 복구할 필요가 없다. 또한 상태 초기화 기능을 사용하여 문제에서 제시한 초기 상태로 다시 돌아갈 수 있다.

학습자별 진도와 명령 시도 이력이 저장되므로 별도의 학습 관리 도구를 사용하지 않고도 학습 진행 상황을 확인할 수 있다. 다만 현재 제공되는 학습 내용은 세 가지 시나리오에 포함된 여섯 개의 문제로 제한되어 있으므로, 현재 상태만으로 정규 Linux 서버 운영 교육 과정을 완전히 대체하기에는 부족하다. 학습 시나리오는 프로그램 코드와 분리된 외부 정의 파일로 관리되므로 새로운 문제를 추가할 때 프로그램 코드를 수정할 필요는 없다.

둘째, 클라우드 및 시스템 관리 학습에 활용할 수 있다. 서비스 상태 확인, 사용자 계정과 권한 관리 및 방화벽 규칙 구성은 클라우드 인스턴스를 관리할 때에도 필요한 작업이다.

특히 네트워크 포트가 허용되어 있더라도 해당 포트를 사용하는 서비스가 실행 중이지 않으면 접속할 수 없다는 구조는 클라우드 환경에서 보안 그룹 설정과 인스턴스 내부 설정을 함께 확인해야 하는 상황과 유사하다. 따라서 본 시스템의 가상 실습은 Linux 서버뿐 아니라 클라우드 인스턴스의 기본적인 접속 장애 원인을 이해하는 데에도 활용할 수 있다.

셋째, 서버 모니터링 기초 학습과 개인용 서버 관리 도구로 활용할 수 있다. 서버 자원 지표의 의미와 정상적인 사용 범위는 고정된 예시만으로 이해하기 어려울 수 있다. 본 시스템은 실제 서버의 자원 사용량을 주기적으로 갱신하여 표시하므로, 고정된 예시 대신 부하에 따라 변화하는 값을 관찰 대상으로 삼을 수 있다.

또한 시스템 전체가 하나의 호스트에서 실행되고 데이터베이스가 하나의 파일로 구성되므로 별도의 복잡한 인프라 없이 개인 서버에 설치할 수 있다. 다만 현재 시스템은 하나의 인스턴스에서 동작하는 것을 전제로 설계하였으므로, 여러 서버를 통합하여 관리하는 용도로는 적합하지 않다.

넷째, 웹 개발과 생성형 AI 연동 교육의 사례로 활용할 수 있다. 본 시스템에는 생성형 AI를 웹 응용 프로그램에 연동할 때 결정해야 하는 여러 설계 사항이 실제 구현에 포함되어 있다.

## 5.4 시스템의 한계

첫째, 실제 학습자를 대상으로 한 사용성 평가와 학습 효과 검증을 수행하지 않았다. 4장의 구현 검증에서 확인한 내용은 시스템이 설계한 방식대로 동작하는지에 관한 것이다. 학습자가 본 시스템을 사용했을 때 기존 방식보다 효과적으로 Linux 서버 운영을 학습할 수 있는지는 측정하지 않았다. 또한 생성형 AI가 제공한 설명의 정확성과 단계별 힌트의 적합성도 평가하지 않았다.

둘째, 생성형 AI의 동작을 완전히 통제할 수는 없다. 본 시스템에서는 생성형 AI에 학습 결과의 판정 권한을 부여하지 않고, 언어모델 호출 지점을 제한하였다. 또한 학습자의 입력을 시스템 지시와 분리된 데이터로 처리하고, 언어모델의 응답에서 사전에 정의한 항목만 허용하도록 검증하였다.

그러나 이러한 장치가 제한하는 것은 언어모델이 시스템에 영향을 미칠 수 있는 범위이며, 생성된 설명 내용의 정확성을 보장하는 것은 아니다. 형식 검증을 통과한 응답에 잘못된 개념 설명이 포함되어 있더라도 현재 구현에서는 이를 탐지하지 못하고 학습자에게 전달할 수 있다.

학습자의 성공과 실패 여부는 규칙 기반 채점기가 결정하므로 생성형 AI의 응답으로 인해 판정 결과가 반대로 변경되지는 않는다. 그러나 판정 결과와 관련된 개념 설명에 오류가 포함되는 문제는 현재 구조로 방지할 수 없다.

이 한계는 개발 과정에서 실제로 관찰되었다. 처리하지 못한 명령을 설명하는 기능에서, 서버가 거부 사유를 명령 이름 때문인지 인자 때문인지 알려주지 않자 언어모델이 시뮬레이터가 지원하는 명령을 두고 존재하지 않는 명령이라고 설명한 사례가 있었다. 해당 단정을 금지하는 지시를 프롬프트에 추가하여 대응하였으나, 이는 확률적 완화이며 결정적 보장이 아니다. 서버가 알려주지 않은 사실을 언어모델이 스스로 보충하려 할 때 그럴듯한 오답이 생성될 수 있다는 점은 구조적으로 차단하기 어려운 부분이다.

셋째, 본 시스템에서 다룰 수 있는 학습 범위와 서버 장애 유형이 제한되어 있다. 가상 상태에서 표현하는 정보는 서비스 실행 여부와 자동 시작 설정, 사용자와 비밀번호, 파일 소유권과 권한, 방화벽 규칙, 패키지 설치 상태 및 이러한 상태를 바탕으로 계산한 원격 접속 가능 여부이다.

파일시스템의 실제 내용, 프로세스의 구체적인 동작, 시스템 로그 및 성능 저하와 같이 현재 가상 상태 항목으로 표현되지 않는 대상은 학습할 수 없다. 명령어 또한 사전에 허용 목록으로 정의된 형태만 처리하며, 명령 연결, 파이프 및 리다이렉션과 같은 셸 문법은 허용하지 않는다. 따라서 여러 가지 원인이 복합적으로 발생하는 실제 서버 장애를 분석하고 진단하는 학습은 본 시스템의 범위에 포함되지 않는다.

또한 모니터링 지표에 대한 생성형 AI 기반 자연어 설명 기능은 구현하지 않았다. 생성형 AI가 설명하는 대상은 가상 실습 상태와 서버의 채점 결과로 제한된다. 모니터링 화면에서 제공하는 실제 CPU, 메모리 및 네트워크 정보는 생성형 AI 기능과 연결되어 있지 않으므로, 각 지표의 의미는 학습자가 직접 판단하거나 별도의 자료를 통해 학습해야 한다.

같은 맥락에서 메모리의 버퍼와 캐시는 자원 수집 단계에서 실제 사용량과 분리하여 전달하지만, 현재 화면에는 별도의 항목으로 표시하지 않는다. 따라서 초보 학습자가 혼동하기 쉬운 메모리 사용량과 캐시의 차이가 화면에 직접 드러나지 않는다.

모니터링 이력 또한 같은 상태이다. 스케줄러가 1분 간격으로 저장한 스냅샷은 기간별 집계, 원본 조회 및 백분위수 통계의 세 가지 경로로 조회할 수 있으나, 이를 호출하는 화면은 구현하지 않았다. 따라서 학습자가 화면에서 확인할 수 있는 추이는 화면을 열어 둔 동안 수신한 값으로 한정되며, 자원 사용의 반복되는 패턴이나 평상시 수준과 예외적 구간의 구분과 같이 긴 기간을 대상으로 하는 판단은 현재 화면으로 수행할 수 없다.

그 결과 실제 배포는 개발용 프로필을 사용하여 이루어졌으며, 사용자와 서버 사이의 통신은 암호화되지 않는다. 이는 구현된 프로그램 기능 자체의 결함이라기보다 배포 환경으로 인해 발생한 제약이다. 그러나 현재 배포 상태를 그대로 외부에 공개되는 서비스로 운영해서는 안 되는 이유가 된다.

마지막으로 실제 운영 환경에서는 본 시스템이 제공하는 AI 응답만을 근거로 서버 조치를 수행해서는 안 된다. 생성형 AI가 설명하는 대상은 운영 중인 실제 서버가 아니라 가상 실습 상태이며, 생성된 설명의 정확성도 별도로 검증하지 않았다. 따라서 본 시스템은 Linux 서버 운영 학습을 지원하는 프로그램으로 사용해야 하며, 실제 운영 판단의 근거로 사용해서는 안 된다.
