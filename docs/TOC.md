1. 서론(이미 작성 완료)
      - 연구 배경
      - Linux 서버 운영 학습의 어려움
      - 기존 모니터링 도구의 한계
      - 생성형 AI 기반 학습 지원의 필요성
      - 본 연구의 목적

  2. 관련 연구 및 기술 배경
      - Linux 서버 모니터링 시스템
		서버 모니터링의 개념, CPU-메모리-디스크 및 네트워크 자원 의미, 시스템 자원 모니터링의 필요성
      - 웹 기반 시스템 관리 도구
		웹 기반 관리 인터페이스의 장점, 기존 서버 모니터링 도구의 주요 기능, 초보 학습자 관점에서의 도구의 한계
      - 시뮬레이션 기반 실습 환경
		초보자가 실제 서버에서 실습할 때의 위험, 실습 환경 격리 방식의 종류(가상머신, 컨테이너, 상태 시뮬레이션)와 각각의 비용·안전성, 명령을 실제로 실행하는 방식과 상태만 전이시키는 방식의 차이, 학습 과제의 성취를 판정하는 기준(명령 문자열 일치와 최종 상태 확인)
      - 생성형 AI와 학습 지원 시스템
		생성형 AI의 설명 및 질의응답 기능, 학습자 맞춤형 피드백의 가능성, 생성형 AI 활용 시 정확성 검증의 필요성
      - Amazon Bedrock
		기본 구조, 대규모 언어모델 호출 방식, 본 시스템에서 Bedrock을 선택한 이유
      - 기존 연구와의 차별성
		기존 시스템이 서버 상태 시각화에 집중한다는 점, 서버 상태 설명과 학습 지원을 결합한다는 점, 초보자 학습 중심의 설명 기능을 제공한다는 점, 명령을 실제로 실행하지 않고 가상 상태의 전이로 실습을 구성한다는 점, 학습 과제의 성취를 명령 문자열이 아니라 최종 상태로 판정한다는 점

  3. 시스템 설계
      - 전체 시스템 구조
		FastAPI 백엔드, React 프론트엔드, Amazon Bedrock, 사용자 간 데이터 흐름
      - 서버 상태 데이터 수집 구조
		CPU, 메모리, 디스크, 네트워크, 로그 및 시스템 정보 수집
      - 백엔드 및 데이터 전달 구조
		FastAPI 기반 REST API, WebSocket 기반 실시간 통신, 수집 데이터의 가공 및 전달 방식
      - 프론트엔드 구조
		React 기반 사용자 인터페이스, 그래프 및 상태 정보 표현, AI 질의응답 인터페이스
	  - 생성형 AI 연동 구조
		서버 상태 데이터의 프롬프트 변환, Amazon Bedrock 모델 호출, AI 응답 생성 및 사용자 전달, 부정확한 응답을 줄이기 위한 프롬프트 설계
      - 가상 Linux 상태 엔진 및 채점 구조
		가상 상태의 표현 방식(서비스, 사용자, 파일 권한, 방화벽, 네트워크), 명령 파싱과 지원·거부 문법의 판정 지점, 상태 전이 규칙과 미지원 명령 시 상태를 보존하는 설계, 최종 상태를 기준으로 성공·부분·실패를 판정하는 규칙 기반 채점, 채점과 문제 선택·힌트·진도 관리의 책임 분리, 학습 시나리오 데이터를 코드 밖에 정의하는 구조
      - 인증 및 실습 환경 격리 설계
		JWT 기반 REST 인증, WebSocket 일회성 ticket의 발급과 1회 소비, 역할 기반 접근 제어의 서버 측 강제, 웹 터미널의 컨테이너 샌드박스 격리 정책, 인증 정보를 URL과 로그에 남기지 않는 설계

  4. 주요 기능
      - 사용자 인증 및 권한 관리
		회원가입과 로그인, JWT 기반 인증, viewer·admin 역할 구분, 서버 측 권한 강제(UI는 표시 전용), 로그인 이력 및 감사 로그 조회
      - 실시간 서버 자원 모니터링
		CPU·메모리·디스크 실시간 그래프, 5초 주기 단일 수집기의 스냅샷 공유(fan-out) 방식, 네트워크 인터페이스·트래픽·패킷·연결 상태 조회, 프로세스 목록 조회와 종료, WebSocket 연결 상태 표시 및 수집 실패 시의 처리
      - 모니터링 이력 조회
		스케줄러의 주기적 스냅샷 저장, 기간·인터벌별 집계 조회, 자원 사용 추이 확인, 원본 스냅샷 보존 기간 정책
      - 웹 터미널 기반 실습 환경
		브라우저 터미널과 Docker PTY 연결, 일회성 ticket 기반 접속 인증, 샌드박스 격리(네트워크 차단, 읽기 전용 루트, 권한 최소화), 가상 파일 탐색기, 실습 환경 초기화
      - 가상 Linux 상태 기반 학습 시나리오
		실제 실행 없이 상태만 전이시키는 시뮬레이션 방식, 서비스·계정·권한·방화벽 시나리오 구성, 지원 명령과 거부 문법의 구분, 최종 상태를 기준으로 하는 규칙 기반 채점, 명령이 달라도 같은 목표 상태면 인정하는 우회 정답 처리
      - 생성형 AI 질의응답 및 설명 생성
		수집된 서버 상태와 가상 실습 상태를 프롬프트로 변환, Amazon Bedrock 모델 호출, 학습 중 자연어 질문에 대한 설명 제공, 대화 이력 관리, 호출량 제한과 오류 발생 시의 대체 응답
      - 학습자 맞춤형 피드백
		단계별 힌트 제공, 명령 시도 이력과 오답 이력 기록, 채점 결과에 따른 진도 관리와 다음 문제 선택, 반복적으로 틀린 개념에 대한 집중 설명
      - 구현 검증
		권한 행렬 전수 검증, 동시 접속 실측, 상태 규칙 엔진의 결정성 확인, 인증 정보의 로그 비노출 확인, 셸 격리 우회 차단 확인

  5. 적용 및 기대 효과
      - 학습자가 서버 상태를 이해하는 과정
		리눅스 서버 모니터링 간접 경험, 리눅스 명령어 학습
      - 단순 실습 환경 제공과 AI 학습 제공의 차이
		학습 중 이해하기 어려운 내용을 자연어로 질문, 실습중인 내용을 ai가 바로 확인, 사용자의시도횟수, 틀린 이력을 바탕으로 어떤 기초가 부족한지 집중 설명
      - 활용 가능성
		Linux 서버 운영 입문 교육, 클라우드 및 시스템 관리 학습, 서버 모니터링 기초 학습, 개인 학습용 서버 관리 프로그램, 웹 개발과 생성형 AI 연동 교육 사례
      - 시스템의 한계
		실제 학습자를 대상으로 사용성을 평가하지 않음, 학습 효과가 검증되지 않음, AI를 100% 통제한다고 확신할 수 없음, 복잡한 서버 장애의 원인을 정확하게 판단하는 데 한계가 있음. 실제 운영환경에서는 AI 응답만을 근거로 조치해서는 안 됨.

6.결론
	- 개발의 의의
		서버 상태 시각화와 자연어 설명 기능을 하나의 프로그램으로 구성, 초보자가 Linux 서버 자원의 의미를 직관적으로 학습할 수 있도록 지원, 기존 모니터링 기능에 생성형 AI 기반 실습 도우미 기능을 결합, 서버 운영 교육에서 생성형 AI를 활용할 수 있는 개발 사례 제시

	- 향후 개선 방향
		실제 학습자를 대상으로 한 사용성 평가, 학습 전후 비교를 통한 학습 효과 검증,  AI 응답의 정확성 평가, Linux 시스템 로그 설명 기능 추가, 사용자 수준에 따른 설명 난이도 조절, 서버 장애 상황별 학습 콘텐츠 확대
